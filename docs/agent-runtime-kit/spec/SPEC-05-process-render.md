## 1. 目标与非目标

### 目标

「过程可见」不是把文本打出来就行。四个真实需求：

1. 文本以**人类可读的速度**出现，但**不能落后太多**（provider 有时一次吐 2000 字符）
2. 工具调用要**一眼看懂在干什么**，状态变化要平滑
3. 默认展开策略要合理（几十个只读调用全展开 = 刷屏；一个文件编辑全折叠 = 看不到改了什么）
4. 忙碌状态有明确指示，且尊重「减少动态效果」

### 非目标

- 不规定视觉设计（颜色、圆角、间距）。
- 不规定组件库。

## 3. 规范条款

### R-05-01 打字必须是追赶式，不是固定速率 · **必须**

**要求**：

1. 落后量 **≤ 阈值**（参考 512 字符）→ **直接全量显示**，不启动任何节奏控制
2. 落后量 > 阈值 → 按分段曲线追赶，每帧吐出的量随落后量递增

**参考追赶曲线**：

| 落后字符数 | 每帧吐出 |
| --- | --- |
| ≤ 12 | 2 |
| ≤ 48 | 4 |
| ≤ 96 | 8 |
| > 96 | `min(256, ceil(size / 4))` |

**理由（最反直觉的一条）**：**正常流式过程中根本不走打字机。** provider 的 delta 本身就是逐字来的，前端合帧后天然是逐字效果。节奏控制只在「一次性收到一大坨」时才启动：重连后的补发、缓存命中的瞬时返回、切换会话时的历史加载。

无条件走打字机会让本来就慢的输出更慢；固定速率会让 5000 字符打半分钟。

---

### R-05-02 打字步进必须落在词/标点边界 · **必须**

**要求**：算出目标位置后，向后最多若干字符（参考 8）寻找空白或标点（参考集合 `[\s.,!?;:)\]]`），对齐到其后。找不到就按原位置切。

**理由**：不对齐会看到 `implemen` → `implementa` 这种单词被切断的效果。

---

### R-05-03 内容被替换（非前缀追加）时必须立刻全量同步 · **必须**

**要求**：新文本不是已显示文本的前缀扩展（`!next.startsWith(shown)`），或长度变短 → 清除节奏定时器，立刻全量同步。

**理由**：权威值覆盖累积值且内容不同的场景（SPEC-03 `R-03-03`）。继续增量会拼出乱码。

---

### R-05-04 生成结束时必须立刻全量 · **必须**

**要求**：`streaming` 变 false → 清定时器，立刻显示完整文本。

**理由**：不能让用户在生成已结束后还看着文字慢慢爬。

---

### R-05-05 进行中的工具不得可展开 · **必须**

**要求**：工具状态为 `pending` / `running` 时，展开交互被禁用（除非显式声明允许）。

**理由**：工具还在跑时内容不完整，展开只会看到半截然后跳变。

---

### R-05-06 工具副标题必须选「一眼认出干了什么」的那个参数 · **必须**

**要求**：为每个工具显式指定副标题来源，**不得**直接 dump 整个 input JSON。

**参考映射**（按你的工具集调整，结构照抄）：

| 工具 | 副标题 |
| --- | --- |
| 读文件 | 文件名（**不是全路径**） |
| 列目录 | 目录名 |
| 通配搜索 / 内容搜索 | pattern（不是路径） |
| 抓取网页 | URL |
| 网页搜索 | query |
| 子任务 | 任务描述 |
| 执行命令 | 完整命令 |
| 编辑 / 写入 | 文件名 |
| 批量补丁 | `N 个文件` |
| 提问 / 待办 | 无 |
| **未注册的工具** | 工具名原样 + 通用图标，**不得崩溃** |

---

### R-05-07 状态标题切换必须提取共同前缀 · **应该**

**要求**：`active` 与 `done` 两个文案提取最长公共前缀，只对后缀做交叉淡入。

**要求**：启用前缀模式的条件是**前缀足够长且两侧后缀都非空**；否则退化为整体交叉淡入。

**要求**：宽度过渡：先锁旧宽度 → 下一帧设新宽度 → 一段时间后解锁回 `auto`。

**理由**：文字长度变化时旁边的内容平滑推移而不是瞬移。

**要求**：无障碍标签始终给出当前完整语义文本，**不得**让屏幕阅读器读到被拆开的前后缀碎片。

---

### R-05-08 默认展开策略必须分级 · **应该**

**要求**：

| 工具类 | 默认 | 依据 |
| --- | --- | --- |
| 执行命令类 | 跟随用户设置 | 输出可能很长 |
| 文件写入类 | 跟随用户设置，**但纯删除除外** | 改动是用户最关心的；「删了 50 行」展开是 50 行红色，无信息量 |
| 其余（只读类） | 折叠 | 这类调用量最大，全展开等于刷屏 |

**「纯删除」判定**：多文件看是否全部操作类型为删除；单文件看 `additions === 0 && deletions > 0`。

---

### R-05-09 重内容必须延迟挂载且从底部优先 · **应该**

**要求**：默认展开的重内容进一个全局挂载队列：

- **后进先出**（LIFO）
- 每个动画帧只挂载一个
- 组件卸载时把自己的任务标记为失效（不必从队列移除）

**理由**：时间线自上而下挂载，但视口在底部。从后往前挂，用户看得见的先可交互。一次挂 20 个大 diff 会冻结一帧。

---

### R-05-10 部分工具不得渲染成时间线卡片 · **应该**

**要求**：维护一个「隐藏工具集」。典型是：

- 待办类工具 → 由专门的待办面板呈现
- 提问类工具**在待回答期间** → 由专门的提问面板承载交互；已回答后才在时间线显示

---

### R-05-11 「用户主动忽略」不得渲染成错误 · **应该**

**要求**：对「用户忽略提问」这类非错误的失败，用中性样式（如右对齐灰字），不用错误卡片。

**理由**：渲染成红色错误卡片会让用户以为出了问题。

---

### R-05-12 计数摘要的分隔符必须是独立可过渡元素 · **应该**

**要求**：`3 reads, 2 searches` 这类聚合摘要：

- 所有条目**始终在 DOM 里**，用属性控制显隐
- 分隔符（逗号）是独立元素，只有「自己有值且前面有值」时显示
- 按固定下标渲染（不重建节点），CSS 过渡才有效

**理由**：从 `3 reads` 变成 `3 reads, 1 search` 时逗号应该是淡入的，不是突然出现。

---

### R-05-13 忙碌指示必须尊重「减少动态效果」 · **必须**

**要求**：`prefers-reduced-motion: reduce` 时关闭动画，但**保留一个静态的"有东西在运行"提示**（如中心元素保持高亮）。

**理由**：全关掉会变成一片死灰，用户看不出系统在运行。

---

### R-05-14 思考标题应从思考内容中提取 · **可以**

**要求**：按优先级尝试提取标题：HTML 标题 → ATX 标题（`# xxx`）→ Setext 标题 → 独占一行的加粗。提取后清理行内代码/链接/强调标记。

**理由**：模型的思考通常自带小标题。提取出来显示成「思考中 — 检查认证流程」，用户不用展开整段就知道在想什么。

## 4. 算法规范

### 4.1 追赶式打字

```
PACE_MS = 24;  IMMEDIATE = 512;  SNAP = /[\s.,!?;:)\]]/

step(size):
    if size <= 12: return 2
    if size <= 48: return 4
    if size <= 96: return 8
    return min(256, ceil(size / 4))

nextIndex(text, start):
    end = min(text.length, start + step(text.length - start))
    max = min(text.length, end + 8)
    for i in [end, max): if SNAP.test(text[i]): return i + 1     # R-05-02
    return end

createPacedValue(getText, isLive):
    shown = getText();  timer = undefined

    run():
        timer = undefined
        t = getText()
        if not isLive():                              sync(t); return   # R-05-04
        if not t.startsWith(shown) or t.length <= shown.length: sync(t); return  # R-05-03
        if t.length - shown.length <= IMMEDIATE:      sync(t); return   # R-05-01 关键分支
        end = nextIndex(t, shown.length)
        sync(t.slice(0, end))
        if end < t.length: timer = setTimeout(run, PACE_MS)

    # 文本变化时的入口判断与 run 内部一致，另加：长度未变或已有定时器则不重复调度
```

### 4.2 工具卡片状态机

```
状态：{ open, ready }
pending() = status in ("pending", "running")

onOpenChange(next):
    if pending() and not allowOpenWhilePending: return            # R-05-05
    if locked and not next: return
    open = next

展开动画：
    打开：overflow = hidden → 动画到 height:auto → 动画结束后 overflow = visible
    关闭：overflow = hidden → 动画到 height:0
```

**动画结束必须把 `overflow` 放回 `visible`**，否则内容里的下拉菜单、悬浮提示会被裁掉。

### 4.3 延迟挂载队列

```
queue = []          # 全局
frame = undefined

schedule(fn):
    item = { active: true, fn }
    queue.push(item)
    ensureFrame()
    return () => { item.active = false }          # 卸载时调用

flush():
    while queue 非空:
        item = queue.pop()                        # LIFO：从底部优先
        if item.active:
            if queue 非空: frame = requestAnimationFrame(flush)
            item.fn()                             # 每帧只挂一个
            return
    frame = undefined
```

### 4.4 状态标题共同前缀

```
common(active, done):
    i = 0
    while i < active.length and i < done.length and active[i] == done[i]: i++
    return { prefix: active[0..i], activeTail: active[i..], doneTail: done[i..] }

useSuffixMode = split.prefix.length >= 2 and activeTail 非空 and doneTail 非空

# 注意："Reading"/"Read" 的 doneTail 为空 → 走整体交叉淡入，不是前缀模式
```

## 5. 可配置参数

| 参数 | 参考默认值 | 可调范围 | 调大 / 调小的影响 |
| --- | --- | --- | --- |
| 打字节奏间隔 | `24ms` | 16 – 40 | 调大：更有打字感但追赶更慢；调小：更快但 CPU 上升 |
| 全量阈值 | `512` 字符 | 256 – 2048 | 调小：更容易触发打字机（正常流式也会走）；调大：几乎只在补发时触发 |
| 边界寻找窗口 | `8` 字符 | 4 – 16 | 调大：更贴词边界但可能一次吐更多 |
| 卡片展开动画 | 约 `350ms`，无回弹 | 200 – 500 | 纯观感 |
| 标题宽度过渡 | `600ms` | 300 – 900 | 纯观感 |
| 忙碌指示动画周期 | `1200ms` | 800 – 2000 | 纯观感 |
| 复制成功反馈 | `2000ms` | 1000 – 3000 | 纯观感 |
| 延迟挂载节奏 | 每帧 1 个 | 1 – 3 | 调大：挂载更快但可能掉帧 |

## 6. 状态 → 视觉对照表

实施时按这张表逐项确认，缺一项就是过程不可见。

| 状态 | 视觉 | 数据来源 |
| --- | --- | --- |
| 文本流式中 | 逐块出现；落后超阈值时按节奏追赶 | `message.time.completed === undefined` |
| 文本完成 | 全量 + 复制按钮 + 元信息（agent · 模型 · 耗时） | `time.completed` 有值 |
| 思考中（无内容） | 「思考中」+ 微光 + 忙碌指示 | `status === "busy"` 且无可渲染 part |
| 思考中（有内容） | 思考内容 + 提取的标题 | reasoning part 有文本 |
| 工具 pending/running | 卡片显示但**不可展开**；标题用进行时 | `state.status` |
| 工具 completed | 可展开；标题交叉淡入到完成时 | `state.status === "completed"` |
| 工具 error | 错误卡片（含可复制的错误文本） | `state.status === "error"` |
| 连续只读工具 | 折叠成「探索中/已探索 + 3 reads, 2 searches」 | SPEC-04 的 context 组 |
| 重试中 | 重试行，带次数/原因/倒计时 | 会话状态为 retry |
| 被中断 | 分隔线 | 中断类错误 |
| 压缩发生 | 分隔线 | user part 中有 compaction |
| 提问待回答 | 时间线**不显示**，由提问面板承载 | 提问工具 pending/running |
| 提问被忽略 | 右对齐灰字 | 特定错误文案 |
| 用户滚开且距底很远 | 「跳到最新」按钮 | SPEC-04 的滚动状态 |

## 7. 反模式

| 反模式 | 后果 |
| --- | --- |
| 固定速率打字机 | 5000 字符打半分钟 |
| 无条件走打字机 | 正常流式也被拖慢 |
| 不对齐词边界 | 看到单词被切成两半 |
| 内容替换时继续增量 | 拼出乱码 |
| 工具跑着时可展开 | 看到半截内容，完成后跳变 |
| 副标题 dump 整个 input | 等于没显示 |
| 展开动画后不恢复 `overflow` | 下拉菜单/悬浮提示被裁 |
| 一次挂载全部展开内容 | 冻结数百毫秒 |
| 计数列表重建节点 | CSS 过渡失效 |
| 逗号不独立 | 突然出现，无过渡 |
| 纯删除也自动展开 | 一片红，无信息量 |
| 减少动态效果时全关 | 一片死灰，看不出在运行 |
| 屏幕阅读器读到前后缀碎片 | 无障碍失败 |
| 未注册工具崩溃 | MCP/插件工具一接入就白屏 |

## 8. 分级实现路径

### 最小可用版（半天）

追赶式打字（§4.1）+ 工具信息映射（R-05-06）+ 基础卡片（可展开/折叠 + pending 禁用）。

### 完整版

补齐状态标题交叉淡入、延迟挂载、计数摘要、思考标题提取、减少动态效果分支。
